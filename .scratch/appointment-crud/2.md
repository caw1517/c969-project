## What to build

Create an appointment from a modal form and see it persisted in UTC and displayed in local time in the grid. Include validation and Add-specific failure handling in this complete path.

## Acceptance criteria

- [ ] Require a selected Customer, trimmed nonempty free-text Type, Start, and End. List all Customers, including inactive ones, by stable ID; initially select none.
- [ ] Offer optional Title, Description, Location, Contact, and URL fields. Trim text and save blanks as empty strings, never NULL. Limit Title and URL to 255 characters; require no URL-format rule.
- [ ] Assign ownership to the logged-in User without a User picker. Capture two complete local date/time values at minute precision with a visible local-zone label.
- [ ] Convert inputs once to UTC and persist exactly the values validated. Explain invalid local clock values without saving.
- [ ] Apply time checks in order: End after Start; both Eastern endpoints weekdays; same Eastern date within inclusive 09:00–17:00 bounds; then global overlap queried at save time on the write connection.
- [ ] Reject overlap regardless of Customer or User, including containment; allow back-to-back appointments. Name the conflict with its title or appointment ID and local times.
- [ ] Parameterize the INSERT and supply all required schema fields, including all six text columns. Use the current User for audit names and UTC for creation time; never write lastUpdate or modify the schema.
- [ ] Handle Add and overlap-query failures in the Add-specific exception path. Failed validation/query/write retains inputs and prevents success. Cancel writes nothing.
- [ ] Refresh after success; distinguish a successful save followed by refresh failure from a failed save.
- [ ] Build and verify minimal-field Add, optional blanks, missing Customer/Type, invalid durations, weekends, out-of-hours and multi-day spans, overlap, adjacent slots, UTC round trip, Cancel, and a controlled Add/query failure in the running app.
